# 研究範圍（暫定）

> 狀態：研究前置階段。本文件記錄研究問題與待驗證的假設，**尚未提出、也尚未實作任何新方法**。
> 本階段的產出是可重現的比較基準（benchmark 與 baseline），不是研究結果。

## 1. 暫定題目

2026-11-11 起的暫定題目（benchmark 規格確定後再定案）：

- 中文：《情境未標註下智能體的情境變動偵測與選擇性記憶利用》
- English: *Context-Shift Detection and Selective Memory Utilization for LLM Agents under Unlabeled Interaction Contexts*
- 前提：論文必須包含情境變動偵測的元件與評估。若之後把偵測降為次要，改用《無情境標註之持續互動中智能體的選擇性記憶利用》。
- 「世界線」不放進題目，只在第一章作為研究動機的比喻，並定義為「人 × 場景的互動情境」。

先前的題目：《無狀態持續型智能體在世界線變動偵測後之選擇性記憶調整》、《動態世界狀態下的智能體選擇性記憶利用》。

## 2. 研究問題

一個 LLM agent 持續與使用者互動，而環境、使用者狀態、事實或情境不斷改變時，agent 應如何管理長期記憶？

現有記憶系統的已知問題（文獻已有描述，見 §4）：

| 問題 | 說明 | 可用來量測的公開 benchmark（見 BENCHMARK_MATRIX.md） |
|---|---|---|
| 記憶累積 | 只存不刪，造成冗餘與檢索干擾 | LongMemEval_S（干擾 session）、Memora（週／月／季長度） |
| 記憶過期 | 情境改變後，舊資訊不再適用 | STALE、Memora（forgetting_absence）、LongMemEval knowledge-update |
| 衝突處理 | 新舊資訊矛盾，需判斷哪一份有效 | STALE（Type I／II）、MemoryAgentBench Conflict Resolution |
| 過度遺忘 | 已失效的資訊仍可能有歷史價值 | Memora FAMA（同時計回憶與遺忘）、LongMemEval temporal-reasoning |
| 情境轉移 | 同一事實在不同時間、情境下可信度不同 | STALE dim2（前提抵抗）、dim3（隱含策略適應） |
| 跨情境推理 | 利用過往情境的經驗協助目前判斷 | 目前沒有公開 benchmark 直接量測（見 §5） |
| 無會話邊界 | 沒有視窗或 session 標記，agent 要自行判斷目前在處理什麼 | SCALE-QA |
| 多人共用記憶 | 同一個記憶庫服務不同對象 | GateMem 的 utility 子集（提問者身分是給定的） |

## 3. 核心構想（尚未實作、尚未驗證）

構想中的處理流程：

```
互動事件 → 記憶抽取 → 情境／世界狀態變動偵測 → 記憶可信度調整
        → Consolidation / Decay / Selective Forgetting → Retrieval → Reasoning
```

「世界線」在本研究中暫時定義為**帶有時間與情境條件的世界狀態或事實版本**，不預設平行宇宙。

想要回答的子問題（都是待驗證的假設，不是已知結論）：

1. 能否偵測新資訊造成的顯性或隱性狀態變動？
2. 能否區分「已失效」、「不確定」、「仍有效但屬於過去情境」三種記憶？
3. 保留歷史記憶是否優於直接刪除？在哪些任務上？
4. 過往情境的記憶能否在目前情境下被部分採信？
5. 能否在減少「依過時資訊推理」的錯誤的同時，保留跨時期經驗？
6. 記憶品質與儲存、檢索、推論成本之間如何取捨？

記憶重要度、時間衰減、情緒權重、知識圖譜關係、情境相似度等機制，目前**不實作，也不預設有效**。

## 6. 2026-11-11 的討論紀錄（方向調整，尚未定案）

研究者對核心構想的補充：

- 世界線會**並存**：同一個記憶庫的 agent 會在不同場景面對不同的人，換環境時不重置記憶。時間不倒流。
- 想避免的失敗是「即視感」：另一個情境的記憶因為相似被取出，並被當成在目前情境也成立。
- 題目中的「無狀態」指**沒有工作視窗或會話邊界**，不是指沒有記憶。文獻中 stateless 通常指後者，題目用詞之後需要調整。
- **隱私洩漏不納入範圍**。關注的是適用性（這條記憶在這裡成不成立），不是權限（能不能說）。

由此得到的暫時判斷：

- 研究主軸從「單一使用者的狀態隨時間改變」移向「多個並存情境之間的記憶誤用與經驗遷移」。
- 只做單一使用者時間軸的空間很小，CUPMem 已經涵蓋主要機制。
- 既有研究的情境標籤都是給定的（SCOPE 的任務類別、GateMem 的提問者身分、ShareMem 的使用者 ID）。「情境需要自行推斷」加上「判斷適用性」的組合，在一輪文獻搜尋中沒有找到直接對應的研究。這只是初步判斷，不是已確認的研究缺口。
- P0 的三個 benchmark 都是單一使用者且 session 邊界給定，只能當作「基本能力沒有退步」的對照，無法支持多情境的主張。
- 「誤用」與「錯失遷移」目前仍然沒有公開 benchmark 直接量測。

## 7. 2026-11-11 採納的研究架構（方法細節尚未定案）

### 7.1 架構

方法的重心從「寫入時偵測世界線變動」移到「讀取時檢查這條記憶在此時此地是否適用」。同一個機制用在兩條軸上：

| 軸 | 檢查的問題 | 評估 | 定位 |
|---|---|---|---|
| 時間軸 | 這條記憶現在還成立嗎 | STALE（官方）；誤殺用 Memora 與 LongMemEval 量測 | 保底，不需要新 benchmark |
| 情境軸 | 這條記憶在這個情境成立嗎 | 混合記憶庫協定（自建） | 特色 |

另外附帶一章：本機模型下的重現與 benchmark 缺陷（LongMemEval 官方 prompt 的證據標記洩漏、Memora 官方 prompt 漏掉使用者發言、Ollama 靜默截斷、小模型 judge 不可靠）。

已決定放掉：時間衰減、重要度、情緒權重、圖資料庫。

### 7.2 這個架構要回答的問題

1. 只對檢索到的記憶做適用性檢查，能不能用遠低於寫入時裁決（CUPMem）的成本，拿到大部分效果？
2. 兩種做法各自會不會把仍然有效的記憶誤判為失效？
3. 情境訊號從「給定」降到「沒有」時，誤用增加多少？讀取時檢查能補回多少？

不論結果往哪個方向，這三個問題都有分析價值。

### 7.4 CUPMem 作為對照組的可行性（已實測）

- 官方程式可以直接指向 Ollama 的 OpenAI 相容端點，不需要修改程式碼。另外需要 `torch`、`transformers` 和本機的 `all-MiniLM-L6-v2`（約 90 MB）。
- 用 `qwen3:0.6b` 在官方資料的第 1 個案例上跑通（只輸入 2 個證據 session）：14 次 LLM 呼叫，約 2.6 萬 token，CPU 上約 5 分鐘。
- 這只是可行性測試：模型太小，寫入端沒有產生任何狀態更新，三個回答都還停留在舊狀態。
- 尚未完成：包成本框架的記憶方法。CUPMem 自己產生最終回答，不只是提供記憶，接入方式要另外設計。

### 8.3 目前的判斷

- 研究者列出的五項能力，每一項都已有附公式和實驗的方法。把它們依序串接不構成方法層級的差異。
- 在已讀的論文中沒有找到的只有兩件事：
  1. 狀態變動**提高**已衰退記憶的可存取性（已讀的方法中，狀態變動只用來降低信任；再活化只由查詢或使用觸發）。唯一提出類似想法的是沒有實作的立場論文。
  2. 衰退和依賴修訂之間的**交互作用**。衰退類方法把記憶當成彼此獨立；修訂類方法假設所有狀態都在圖中、隨時可取用。
- 公開 benchmark 的限制：對話都不長，衰退幾乎不會成為限制因素（HeLa-Mem 的消融是直接證據）；也沒有任何一個量測「狀態變動後，舊經驗重新變得有用」。

### 9.2 ValidMem 的實際內容（已下載檢查）

- 466 個案例、1,393 條記憶，CC-BY-4.0；439 個英文、17 個中文、10 個混合。
- **每個案例的記憶庫只有 2–5 條記憶**（平均 2.96）。檢索幾乎不會失敗，所以量不到衰退或喚醒的影響（MemFSM 論文另有每案例加入 30 條干擾的 Hard30 設定）。
- README 說每個案例都配對「現在」和「歷史」兩種提問，但資料檔每個案例只有一個 `query`；子類別 `historical_query` 只有 20 題。這點在使用前要再向原作者確認。

### 9.3 STALE 衰退診斷的結論

細節見 DIAGNOSTICS.md §1。重點：

1. 不衰退時，寫入時裁決能找到舊記憶（93.5%）。
2. 照 FadeMem 論文的參數衰退，提問時取得新證據的比例從 65.1% 掉到 6.3%。在沒有中途存取的情況下，純時間衰退在 STALE 上等於只記得最近的事。
3. 在 Pragma 式「寫入時排除沉寂、提問時可喚醒」的分工下，96.8% 的案例會出現**舊記憶在新證據到來時無法被重新詮釋，提問時卻被喚醒取回**。（**已修正**：Pragma 每一輪對話都會喚醒，實際比例介於 47.7% 到 96.8% 之間，見 §10 和 DIAGNOSTICS.md §1.6。）

### 9.4 目前的判斷（尚待答題層級的證據）

- 研究者列出的「情節記憶＋衰退＋喚醒＋重新理解＋保留歷史」組合，Pragma 已在同一個系統中實作；「強度不等於有效性」MemFSM 已形式化；「情境條件下的適用性」有 RaMem、MINDSET、MemConflict。**這些都不能再作為貢獻**。
- 已讀文獻中找不到、且診斷顯示確實會發生的，是**衰退與修訂的交互作用**：既有系統的修訂（重新詮釋、失效判斷、依賴傳播）只看得到當下可取用的記憶，而衰退恰好讓最需要修訂的舊記憶不可取用；喚醒又只由提問觸發，喚醒時不會順便修訂。
- 由此得到一個最小、可驗證的方法方向：**修訂與喚醒由同一個事件觸發**。新證據到來時，從所有記憶（含沉寂者）找出受影響的候選，修訂它們並調整可存取性；或在提問喚醒時，先依喚醒後到現在之間的新證據修訂，再交給答題模型。是否比「分開運作」好，正是 RQ3，可在 STALE 上用 2×2 消融驗證。
- 尚未排除的反例：答題模型可能本來就會在 context 中同時看到新舊證據而答對；若答題層級的分解顯示「新證據在 context 但仍答錯」才是主因，研究重心應移到使用端，而不是修訂端。


## 10. 2026-11-11 第五輪：讀完 Pragma 正式論文後的修正

研究者提供了 Pragma 論文 PDF（Santi 2026, *Knowledge-Based Systems* 353:117193）。

### 10.1 論文確認了什麼

- **宣稱的新穎性**：作者明說沒有前例的只有一件事：情節與信念兩層的版本化重新詮釋，事件敘事不在可改寫的範圍內。衰退、喚醒、可編輯記憶各自都承認有前例。所以研究者原本的「依證據重新理解、不覆寫歷史」正是 Pragma 主張的貢獻。
- **流程順序是刻意設計的**：遺忘掃描在重新詮釋之前執行，「讓已跨過沉寂門檻的情節不成為一般候選」（§2.2）。重新詮釋只在「至少一個活躍的過去情節主題相近」時執行（Table 3）。
- **Curator 每一輪對話都會執行**，候選包含沉寂情節，選中即喚醒（Table 3；原始碼 `curator.py`）。
- **評估**：4 個自編情境（一週、一學期、五年、四十年）× 4 個模型家族 × 每組 10 次，共 229 次執行。量的是狀態轉移有沒有發生（追蹤紀錄），不是答題正確率。
- **作者自己劃的界線**：拿掉整套生命週期、只用關鍵字前 k 筆的對照組，在 5 個記憶探測題上全對（25/25），和完整架構無法區分。原因是每次只有 5–9 個情節，檢索太容易。作者明說：衰退和選擇性喚醒預期有用的情境，是「相關情節無法全部放進有限 context」的大型記憶庫，這次沒有達到，留待後續研究。
- **作者自列的下一步**：喚醒強化不分原因（為了找檔案位置而回憶，和為了重大事件而回憶，加的分數一樣）；重新詮釋沒有驗證是否有證據支持，錯誤的重新詮釋會傳到語意層。

### 10.2 對先前結論的修正

1. **「喚醒時不會修訂」只對一半**：Pragma 在同一個 session 中先由 Curator 喚醒、結束後再重新詮釋，已經隱含地把兩者接起來。缺的是喚醒的標準：Curator 為「回答當下對話」挑選，不是為「找出會被新證據推翻的記憶」挑選。
2. **被遮蔽修訂的比例要改成區間**：47.7%–96.8%（DIAGNOSTICS.md §1.6）。下界要靠 Curator 每次都選 m_o 才達得到，實際值需要用本機模型實測。
3. **修訂觸及率的另一個瓶頸是候選數上限**：即使不衰退，「最相近的 3 個情節」也只涵蓋 53% 的 m_o。

### 10.3 目前的判斷（取代 §9.4 中「已讀文獻中找不到」那一點）

- **原本的候選缺口變弱了，但沒有消失**。還能成立的版本是：**以「是否受新證據影響」為標準的喚醒**，也就是新證據到來時，主動到沉寂區找出可能被推翻的記憶並交給修訂，而不是等它碰巧對回答當下對話有用。它和 Pragma 的差異是**選擇標準**，不是有沒有耦合。這個差異有多大，取決於上面那個實測：如果 Curator 本來就幾乎都會選 m_o，差異就很小。
- **另一個浮現的方向是評估本身**：Pragma 作者明說「大型記憶庫下衰退與喚醒是否有用」還沒有人量過，而 STALE（50 個 session、新舊證據相隔中位數 244 天）正好是那個規模。但這是**評估貢獻**，不是方法貢獻；而且作者已公開預告這是他的下一步，有被搶先的風險。
- **論文自列的兩個下一步**（依原因加權的喚醒強化、重新詮釋的證據驗證）也和研究者的構想相關，但同樣有被原作者搶先的風險，而且都不是研究者最初想解決的問題。
- 決定重心之前，最需要的兩筆證據（判斷門檻預先寫在 DECISION_GATES.md）：
  1. Curator 選擇率實測（DIAGNOSTICS.md §1.6 最後一段）：決定「依影響喚醒」與 Pragma 的差距；
  2. STALE 答題層級的錯誤拆解（DIAGNOSTICS.md §1.5）：決定問題在檢索端還是使用端。

### 11.2 判斷

1. **「用圖譜找出受影響的記憶」本身不是新方法**。直接矛盾已由 Graphiti、Mem0g 處理；沿依賴邊遞移失效是真值維護系統的經典做法，2026 年至少有 Tether、rollback、PACMI、StateGraph、MemTX、MemoRepair 用在 agent 記憶上；「先依更新解析再沿圖選證據」有 CMC。
2. **多篇作者都指向同一個未解決的步驟：推論對話中沒有明說的依賴**。
   - Tether：需要推論才得到的依賴沒有測。
   - rollback：從自然語言推論缺少的邊不在範圍內。
   - CMC：只處理明確的單一值斷言。
   - StateAuditor：瓶頸在抽取，不在驗證。
   - *Stale, Misattributed, or Late*：7B 本機模型歸併更新的召回率不超過 0.062。
3. **本機小模型的條件同樣沒人做好**：StateAuditor 的 4B 蒸餾失敗；Tether 用較弱的寫入模型會漏掉依賴。
4. **STALE 上已有強對手**：StateAuditor 直接在 STALE 上做，任何在 STALE 上的方法都必須和它比較。它使用前沿 API 模型，本機模型的條件尚無人報告。
5. **和實驗 A 有關的外部證據**：StateAuditor 引用 STALE 論文的數字：CUPMem 的狀態辨識 91%，但隱含策略調整只有 32%；隱含策略調整答錯的案例中，67.8% 新證據其實已在 context。這支持「使用端錯誤很多」，但實驗 A 仍照預先登記的規則執行，以我們自己的數字為準。
6. **被搶先的風險很高**：同一團隊在三個月內發表了 StateGraph、PACMI（推測）、Tether、rollback 等多篇。

| 1. 過時記憶在哪個階段處理 | 原本的差異在「同一個本機模型下比較」。拿掉本機條件後，StateAuditor 已在前沿模型下比較過答題後稽核與「寫入端裁決摘要」等做法，**差異大幅減弱，不再適合當主線** |
| 2. 推論沒說出口的前提 | **不受影響**。前沿模型也做不到：StateAuditor 的 gpt-5.5 稽核在隱含策略調整上的舊前提召回率只有 0.38，few-shot 或思維鏈反而降到 0.13；Tether 明說需要推論的依賴沒有測 |
| 3. 取到了卻沒用上 | StateAuditor（答題後稽核）與 A-TMA（狀態標示）已涵蓋，拿掉本機條件後差異很小 |
| 4. 衰退在什麼規模下才有用 | 不受影響，但屬於評估貢獻，Pragma 作者已預告 |
| 5. 同一個記憶庫面對不同的人或場景 | 不受影響，但需要撤回「不自建 benchmark」的決定 |

### 13.2 判斷

1. **已有的三條線各自假設了一件事**：
   - 跨使用者共享（MixUA、ShareMem、GateMem）：**身分給定**。
   - 多人群組記憶（GroupMemBench、SpeakerMem-R1）：**發言者標註給定**。
   - 情境適用性（PairPref、TANGLE、CUPID、RPEval）：**單一使用者**，情境寫在提問裡或明確缺少。
2. **沒有找到的組合**：純文字、**沒有身分標註也沒有對話視窗邊界**的連續互動中，同時決定「這條記憶屬於哪個人或場景」和「它現在適不適用」。唯一處理「身分不給定」的是 EvoSpeakerMem，但它靠聲紋。這正是研究者最初的構想：不開多個視窗、同一個記憶庫面對不同的人與場景。
3. **可以借用的現成評估**：PairPref（情境適用性）和 TANGLE 的 CPC 子集可作為方法的外部驗證，不必全部自建。
4. **風險**：
   - MixUA 一週前才發表，相鄰團隊可能延伸到身分不給定的情況。
   - 沒有任何訊號時（`none` 條件），閒聊類 session 本身可能看不出是誰，有落在地板的風險（MIXED_MEMORY_PROTOCOL.md §3.9），要先做可行性檢查。
   - 「場景」的定義比「人」模糊，需要先定義清楚才能建 benchmark。

### 13.3 「沒有任何訊號」是不是真實且沒人解決的問題（研究者提問，2026-11-11）

- **真實存在**：CMU 等人的範圍回顧（arXiv:2609.14062，58 篇研究）整理出多人共用單人設計助理的途徑：共用帳號（例如為了分攤訂閱費）、家庭與車用的共用助理、群組對話。其中記錄的風險包括「共用的助理情境把一個人的對話歷史連到另一個人，在家庭、照護、共乘車輛中造成錯誤的個人化」。
- **已有的回應多半靠聲音或帳號**：聲紋（EvoSpeakerMem）、擁有者限定的收音、帳號與權限。純文字、沒有帳號區分時，從內容推斷歸屬並據以決定記憶適用性，在已讀的文獻中沒有方法。
- **但要誠實界定**：有帳號的服務通常知道「是誰」，卻不知道「在什麼場景、對誰說話」。研究者定義的複合場景（同一個人在不同場景面對不同的人）中，場景這一軸在實務上幾乎都沒有標註。所以「none」的真實版本，比較準確的說法是「情境（人 × 場景）沒有標註」，而不只是「不知道使用者是誰」。
- **可行性**：見 MIXED_MEMORY_PROTOCOL.md §7。Memora 的內容幾乎不帶身分線索，不適合當 `none` 條件的資料。GroupMemBench（arXiv:2605.14498）每位使用者都有固定的語氣與風格組合（抽樣時不重複），也有專案、主題、階段等場景結構，若把發言者標註拿掉，可能是更合適的來源；授權與取得方式待確認。

### 14.2 差異點是否成立

成立，但要寫得精確。已讀文獻中沒有同時具備以下四點的工作：（1）純文字；（2）沒有身分與場景標註；（3）跨天、跨週的長期再辨識；（4）歸屬結果直接決定記憶是否適用。最接近的 SpeakerBind 和 EvoSpeakerMem 都靠聲音，SCALE-QA 只有單一使用者的主題軸，對話分離只處理短距離。

### 14.3 GroupMemBench 重組成「一人一段相處」的評估

`python -I scripts/diagnose_attribution_groupmem_blocks.py <domain>.json`。一段相處 = 同一位作者在同一頻道同一天的所有訊息；頻道視為場景；每段找最相近的**先前**段落（完全不用標註），再用標註計分。

| 領域 | 作者 | 頻道 | 每人參與的頻道 | 段落數 | 每段訊息數（中位數） | 最相近的先前段落：同作者 | 同頻道 | 兩者都同 | 作者隨機 |
|---|---|---|---|---|---|---|---|---|---|
| Healthcare | 6 | 10 | 7.0 | 1,323 | 19 | 34.5% | 98.4% | 33.8% | 16.7% |
| Technology | 18 | 7 | 2.3 | 1,040 | 20 | 26.2% | 99.0% | 26.1% | 5.6% |

解讀：

- **場景幾乎都認得出來（98%–99%）**，因為每個頻道是不同專案，用詞差異大。**難的是同一場景裡「是誰」**：比隨機好 2–5 倍，但遠低於完美。所以在這份資料上，複合情境的難度幾乎都落在「人」的軸。
- 2%–6% 的訊息直接寫出 `User_N`，`@QA`、`@platform` 等團隊標記也會透露角色，重組時要遮蔽或另外報告。
- **結構上的落差**：GroupMemBench 的訊息是人對人說的，重組後的段落沒有代理的回覆，回覆的對象也在別的段落。用來測歸屬可以；用來測「代理和每個人一對一相處」的記憶使用，真實性有限。
- GroupMemBench 的題目綁定提問者（在程式庫中，MIT 授權，尚未下載），「提問者藏在『我』後面」那一類題目拿掉標註後，正好是本研究要考的情況。

### 14.4 建議

1. **先用 GroupMemBench 重組版當第一份衍生資料**：取得快，能先驗證方法流程，標示為 `derived_protocol`。
2. **自建資料要把「線索強度」當成可控變數**：從 SpeakerBind 式（文字幾乎沒有線索）、GroupMemBench 式（角色用語），到強線索（固定語氣、常提的人事物），報告方法隨線索變弱如何退化。這比只報一個總分更有說服力，也回應「合成資料不真實」的質疑。

### 14.5 先前的衰退相關成果在新方向中的角色（2026-11-11）

- **FadeMem 一類的強度衰退不再是方法的核心**，但保留三個用途：
  1. **對照組**：依強度、時間排序的記憶使用（FadeMem 衰退曲線、Pragma 式沉寂與喚醒），代表「依記憶強度選擇」；本研究的方法代表「依情境適用性選擇」。兩者的對比就是研究者最初提出的「記憶強度 ≠ 情境適用性」。`src/wlmem/memory/decay.py` 與 rag 的 `decay` 參數可以直接沿用。
  2. **論證材料**：STALE 診斷顯示，照 FadeMem 參數做全域時間衰退時，提問時取得新證據的比例從 65.1% 掉到 6.3%（DIAGNOSTICS.md §1）。這可以說明為什麼不採用以牆鐘時間為準的全域衰退。
  3. **可能的小元件（未驗證）**：以「距離上次處在同一情境多久」取代牆鐘時間來計算衰退，也就是每條世界線各有自己的時鐘。是否有效、是否已有人做過，要等方法設計時再查。
- 時間軸上的「過時記憶」（STALE、喚醒與重新詮釋）列為未來工作。

## 15. 2026-11-11 研究者提問：「利用時間性圖結構穩定度輔助記憶保留，並透過情境有效性控制記憶的抑制與重新啟用」

### 15.1 前半段（以圖結構決定記憶保留）的已有研究

| 論文 | 做法 | 結果或限制 |
|---|---|---|
| **EngramRAG**，arXiv:2609.32049 | 以 Hebbian 共同取回強化邊權；**依拓樸「承重程度」（中心性、度數、類型）調整衰退半衰期，而不是依牆鐘時間**（CATD），解決「基礎事實被時間衰退抹掉」；以 SUPERSEDES 邊抑制過時事實 | 90 天模擬中基礎事實保留 100%（時間衰退 60%）；LoCoMo 檢索提升，但下游答題 F1 與基準相當 |
| *Selective Forgetting*，arXiv:2608.28978 | 依近期性、頻率、**度中心性**、年齡給節點打分並修剪 | 圖記憶在 LongMemEval 上**不如**一般向量檢索（F1 0.417 對 0.468）；遺忘只省下約 10% 儲存，答題幾乎不變 |
| FluxMem，arXiv:2605.28773 | 連結隨回饋增刪，長期鞏固成穩定的程序迴路，以成熟度指標判斷收斂 | — |

### 15.2 判斷

1. **前半段空間很小**：「依圖結構而不是時間決定保留」已有 EngramRAG 直接做了；「時間性的穩定度」只是中心性、共同啟動等訊號的變形。而且多篇研究顯示，保留與遺忘在現有 benchmark 上量不出答題差異（HeLa-Mem、Pragma、*Selective Forgetting*）。
2. **後半段就是目前的主線**：依情境決定抑制與重新啟用。但若題目沒有寫出「情境未標註」，就會和 Pragma（沉寂與喚醒）、MemFSM（有效性與可見性）、MixUA（範圍）、*Towards Reversible Forgetting*（情境再現時恢復）重疊，失去差異點。
3. **可能的改寫（未查證是否有人做過）**：把「穩定度」改成跨情境的穩定度。一條經驗若在多條世界線中反覆出現且一致，就視為可遷移；只在單一世界線中出現，就視為只屬於該情境。這樣圖結構的訊號是用來判斷**適用範圍**，而不是判斷**保留與否**，能和主線接起來。

### 15.3 查核：「以跨情境的一致性判斷記憶適用範圍」是否已有人做（2026-11-11）

| 論文 | 怎麼決定一條經驗適用多廣 | 情境是否給定 |
|---|---|---|
| **Scope Before You Persist**，arXiv:2609.29144 | 原則：**證據來自哪裡，就只在那裡使用**。通過檢驗的技能只部署到產生它的任務家族；全域部署時，局部有效的修改會傷害其他家族（12 次接受中 6 次有害，限定範圍後 63 次中 0 次）。**範圍只會鎖在來源，不會因為在多個家族都成立而放寬** | 任務家族是給定的（或由在標註資料上訓練的分類器判斷） |
| **MixUA**，arXiv:2611.10439 | LLM 寫入時指定四種範圍之一；定期審查時，「同一件事出現在不同範圍的兩條紀錄，就是把兩者都放寬的理由」。**這已經是「跨情境重複出現 → 放寬範圍」的規則**，只是由 LLM 判斷 | 使用者、代理身分給定 |
| Pragma（KBS 353:117193） | 信念至少要兩個不同來源的情節才能成立 | 跨情節，不是跨情境 |
| LifeMem，arXiv:2609.12655 | 依工作流程把不同環境的軌跡分群，從每群抽出「與環境無關」的技能 | 環境標籤給定 |
| STRATA，arXiv:2610.19386 | 以社群偵測把相似工作流程歸納成上位框架；用「相反操作」的對比邊防止負遷移 | 任務給定 |

**判斷**：

- 「跨情境重複出現就可以遷移」這個想法，MixUA 的審查規則和 Pragma 的兩來源門檻都已部分涵蓋；「證據範圍決定使用範圍」則是 *Scope Before You Persist* 的核心主張。**它不能單獨當成貢獻，也不宜放進題目。**
- 仍然不同的地方：上述工作的情境（使用者、任務家族、環境）都是給定的。在本研究中，情境本身是推斷出來的，而且推斷可能出錯，所以範圍判斷必須考慮「這幾條紀錄真的來自不同情境嗎」。這可以作為方法中的一個元件：**以推斷出的情境為單位，依支持證據的情境數量與一致程度放寬或收窄適用範圍，並把情境歸屬的不確定性納入判斷**。
- 題目維持《情境未標註下智能體的情境變動偵測與選擇性記憶利用》。

## 16. 2026-11-12 研究者轉述另一個模型的建議：《基於時間演化圖結構穩定度與情境有效性之智能體記憶選擇性利用研究》

## 17. 2026-11-12 研究者提問：從「記憶遺忘」出發，現在的題目是更複雜還是更有貢獻？能否回到遺忘？

**判斷**：兩者都有，但現在的題目並沒有離開遺忘。

- **現在的題目可以定位為「情境依存的遺忘」**：記憶不是消失，而是在不對的情境中不該被提取（心理學的情境依存記憶與編碼特定性原則；寫論文時需查證並引用原始文獻）。C3 就是依情境決定記憶能不能取用；失敗可以直接量（誤用、漏用），這正是全域遺忘缺少的評估。

**選項**：A. 維持現題，論述強調情境依存的抑制；B. A 再加「依情境過時」的事實；C. 回到純遺忘方法（擁擠，且需先建一個遺忘會改變答案的 benchmark）。
