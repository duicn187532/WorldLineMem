# 決定研究重心的判斷門檻（預先登記）

狀態：**已停用（2026-11-11）**。研究者把主線改為「同一個記憶庫面對不同的人與場景」（RESEARCH_SCOPE.md §13），實驗 A、B 不再用來決定研究重心。門檻曾於同日確認；兩個實驗都沒有執行過，也沒有任何結果。腳本保留供分析章節使用。建立日期：2026-11-11。

確認後要把這份文件連同 commit 雜湊記在 §7。之後才開始跑實驗 A、B。**看到結果後不得修改門檻**；若真的需要改，在 §7 寫下改了什麼、為什麼，並在論文中說明這是事後調整。

## 1. 目的

研究順序的第 3 步是「決定重心：喚醒、重新詮釋，或兩者的協同決策」。讀完 Pragma 論文後，剩下的候選方向是**依「是否受新證據影響」來喚醒**（RESEARCH_SCOPE.md §10.3）。它能不能成立，取決於兩個還沒量的數字：

- **實驗 A**：STALE 上的答錯，主要錯在「新證據沒取回」（檢索端），還是「新證據已在 context 仍答錯」（使用端）？
- **實驗 B**：Pragma 的 Curator 在新證據到來的 session 中看到舊記憶時，會不會選它？

這份文件預先寫下：每個數字落在哪裡，就走哪個方向。

## 3. 實驗 A：答題層級的錯誤拆解

**設定**：全部 400 個 STALE 案例、1,200 個探測問題。

| 設定檔 | 角色 |
|---|---|
| `configs/local/stale__rag_bm25.toml` | 主要（不衰退） |
| `configs/local/stale__rag_bm25_decay_fademem_sml.toml`、`..._fademem_lml.toml`、`..._halflife30.toml` | 衰退的影響 |

跑完 `wlmem run`、`wlmem evaluate` 後執行 `python scripts\decompose_stale_errors.py runs\<run_name>`。

**指標**（都在 `stale__rag_bm25` 上計算，除非另外註明）：

| 編號 | 定義 | 用途 |
|---|---|---|
| A1 | 使用端錯誤比例 U＝「新證據在 context 且 judge 判錯」÷「所有判錯」 | **主要判斷** |
| A2 | 新證據在 context 時，「舊證據也在」與「舊證據不在」的通過率差距 | 描述用。這是觀察資料，有干擾因素，不做因果宣稱 |
| A3 | 各衰退設定相對於不衰退的 Overall 差距，以案例為單位做成對 bootstrap（10,000 次）的 95% 信賴區間 | 判斷衰退本身是否有益 |

**門檻（草案）**：

| A1 | 判定 |
|---|---|
| U ≥ 0.60 | **使用端為主** |
| 0.40 < U < 0.60 | 兩端並存 |
| U ≤ 0.40 | **檢索端為主** |

| A3 | 判定 |
|---|---|
| 三個衰退設定的信賴區間上界都 < 0 | 純時間衰退在 STALE 上有害。方法若保留衰退，必須以準確率以外的理由說明（例如 context 預算），並把「不衰退」列為必要對照組 |
| 任一設定的信賴區間下界 > 0 | 衰退有益，和檢索層診斷相反，要先查明原因再往下走 |
| 其他 | 衰退對準確率沒有可辨識的影響 |

## 4. 實驗 B：Pragma Curator 的選擇率

**設定**：`configs/local/pragma_curator.toml`，`scripts/measure_pragma_curator.py`（流程和沒有模擬的部分寫在腳本開頭）。

```powershell
python scripts\measure_pragma_curator.py configs\local\pragma_curator.toml --pragma <Pragma checkout> --sample 100 --seed 0
```

- 案例順序由 `seed` 決定並固定。`--sample 200` 的前 100 個就是 `--sample 100` 的那 100 個，所以擴大樣本時不必重跑。
- 100 個案例約需 3,300 次情節整理呼叫（STALE session 中位數約 3,600 token）和 470 次 Curator 呼叫；200 個案例約 6,100 次和 930 次。先跑 1 個案例量單次延遲，再估算總時間。
- 整理結果會快取，中斷後重跑同一指令即可續跑。

**指標**：

| 編號 | 定義 |
|---|---|
| B1 | 在「至少一輪被列為候選」的案例中，模型至少一輪選了舊記憶的比例（排除 Curator 失敗後的確定性退回），附 Wilson 95% 信賴區間 |
| B2 | session 結束後，舊記憶落在重新詮釋目標（最相近的 3 個活躍情節）中的比例 |
| 參考 | 舊記憶標示為沉寂時的選擇率；模型給的用途標籤（substantive／procedural） |

**門檻（草案）**：

| B1 | 判定 |
|---|---|
| ≥ 0.80，且信賴區間下界 ≥ 0.70 | **Pragma 已隱含涵蓋**：Curator 為回答當下對話挑選時，本來就會選到舊記憶。「依影響喚醒」與 Pragma 差異太小，放棄這個方向 |
| ≤ 0.50，且信賴區間上界 ≤ 0.60 | **有空間**：「依影響喚醒」可以進入方法設計 |
| 其他 | 差異弱，交由實驗 A 決定 |

**樣本擴大規則**：B1 的點估計與任一門檻（0.80、0.50）相差不到 0.05 時，擴大到 `--sample 200` 一次，以 200 個案例的結果為準。只擴大一次。

**B2 的附帶判讀**：若 B1 高但 B2 < 0.50，代表瓶頸在「每次只重讀 3 個」的上限，而不是喚醒標準。這是參數層級的問題，不足以構成方法貢獻，只在論文中當作觀察報告。

## 5. 決策矩陣

| | B1 高（Pragma 已涵蓋） | B1 中 | B1 低（有空間） |
|---|---|---|---|
| **U 高（使用端）** | 轉向**使用端**：答題時區分現行與歷史記憶的選擇性利用 | 同左 | 使用端為主；「依影響喚醒」最多當次要元件 |
| **U 中** | 使用端 | 重新討論；再補一筆證據（例如以 dense 檢索重跑實驗 A） | 「依影響喚醒」為主，使用端當對照 |
| **U 低（檢索端）** | 問題在提問時取不到新證據，不是喚醒標準。回到文獻比對（MemFSM 的有效性路由等），目前**沒有明確差異點** | 「依影響喚醒」，但需要先補證據 | **「依影響喚醒」**（原候選方向）進入第 4 步 |

「轉向使用端」的理由：它直接對應研究者最初「選擇性利用」的構想；MemFSM 只在每個案例 2–5 條記憶的規模上驗證過（ValidMem），STALE 規模下的表現還沒有人報告。進入第 4 步前，要先依 RESEARCH_SCOPE.md 的方式，對使用端做同樣嚴格的文獻比對。

## 6. 不會因為結果而改變的事

- 不自建 benchmark，不修改 STALE 的資料、題目或評分準則。
- 不以 gold 欄位或測試答案作為記憶建構的輸入；gold 只用於計分。
- 只用本機模型。所有結果標示 `local_adaptation`；容器裡用小模型跑的只算 `smoke_test`。

### 7.1 提議的前置條件修正（待確認）

用 qwen3:0.6b 在容器裡跑 1 個案例的流程檢查（`smoke_test`，不是實驗資料）發現兩件 0c 量不到的事：

1. **小模型會照抄 Pragma 提示裡的範例**。新證據那個 session 被整理成「Recorded a production outage caused by a Friday deploy; lesson: never release on Friday」，這是 Pragma 整理提示中的示範句，和對話內容無關。Pragma 只把 `...` 佔位符當成整理失敗，所以這種情節不會被標為「退化」。32 個情節中有 9 個（28%）照抄提示。
2. **同樣的 Curator 呼叫，重跑結果可能不同**。溫度 0、固定 seed，4 次重跑中有 1 次選擇不同。Pragma 論文也報告過執行環境殘留的不確定性。

提議：

| 編號 | 條件 | 提議門檻 |
|---|---|---|
| 0c（擴充） | 除了原本兩項，**照抄提示的情節**（與整理提示共有任一段連續 6 個字、且該段不在對話原文中）≤ 5%。腳本輸出 `echo_episode_share` | ≤ 5% |
| 0e（新增） | Curator 的決定可重現：同一批 20 個案例的 Curator 呼叫重跑一次（情節整理用快取，不重跑），以「每輪選中的情節集合是否相同」計算一致率 | ≥ 95% |

0e 的做法：把第一次的 `episodes.jsonl` 複製到另一個 `--out` 資料夾，用 `--sample 20` 重跑，再比對兩邊 `cases.jsonl` 中每輪的 `chosen`。
