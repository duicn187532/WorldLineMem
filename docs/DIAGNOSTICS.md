# 診斷實驗

這裡記錄為了收斂研究問題而做的診斷。診斷不是研究結果，也不和任何論文數字並列。

## 1. STALE × 時間衰退：檢索層診斷（2026-11-11）

**目的**：確認時間衰退會不會妨礙「新證據出現時修訂舊記憶」，以及會不會讓新證據在提問時取不到。

**重現**：`python scripts/diagnose_stale_decay.py --out runs/diagnostics/stale_decay`（約 70 秒，不需要任何模型）。

### 1.1 設定

- 全部 400 個 STALE 案例；記憶單元是一問一答；檢索器 BM25；主要報告 top-10。
- 時間取自 STALE 官方的 session 時間戳記。提問時間設為最後一個 session 的時間（STALE 沒有提問時間）。
- STALE 的證據位置（`relevant_session_index`）**只用來計分**，不進入記憶。
- STALE 的時間結構：舊證據 m_o 在第 0–14 個 session，新證據 m_n 在第 30–39 個；m_o 到 m_n 中位數 244 天，m_n 到提問中位數 100 天。

量測兩個時間點：

| 時間點 | 記憶內容 | 查詢 | 量的是 |
|---|---|---|---|
| 寫入時 | 第 0 到 n−1 個 session | 新證據 session 的使用者發言 | 寫入時裁決（CUPMem、StateGraph、Pragma 的重新詮釋）能不能找到要修訂的舊記憶 |
| 提問時 | 全部 50 個 session | 三個官方探測問題 | 新、舊證據能不能被取回 |

衰退設定（`src/wlmem/memory/decay.py`，**只實作 FadeMem 的衰退曲線**，即論文式 4–6；論文沒公開 μ 和重要度的算法，這裡設為 0；沒有存取強化、衝突消解、融合）：

| 名稱 | 曲線 | 排序方式 |
|---|---|---|
| none | 不衰退 | BM25 |
| fademem_sml | λ=0.1/天、β=1.2（論文值，半衰期約 5 天） | 相關度 × 強度 |
| fademem_lml | λ=0.1/天、β=0.8（論文值，半衰期約 11 天） | 相關度 × 強度 |
| halflife30 | 指數衰退，半衰期 30 天（Pragma 預設） | 相關度 × 強度 |
| fademem_lml_dormant | 同 fademem_lml | 強度 < 0.15 的單元不參與檢索 |
| pragma_dormant | 半衰期 30 天、初始強度 0.5、門檻 0.15 | 同上，寫入時和提問時都排除 |
| pragma_revive | 同上 | **寫入時排除沉寂記憶，提問時可喚醒**（只模擬了「提問」時的喚醒；Pragma 其實每一輪對話都會喚醒，見 §1.6 的修正） |

### 1.2 結果（top-10，400 個案例、1,200 個探測問題）

| 設定 | 寫入時找得到 m_o | 寫入時 m_o 已沉寂 | 提問時取得 m_n | 提問時取得 m_o | 寫入時找不到、提問時卻取得 m_o |
|---|---|---|---|---|---|
| none | 93.5% | 0.0% | 65.1% | 89.6% | 6.5% |
| fademem_sml | 0.3% | 99.8% | 6.3% | 0.2% | 0.0% |
| fademem_lml | 0.8% | 97.8% | 12.2% | 1.5% | 1.5% |
| halflife30 | 1.5% | 94.0% | 19.3% | 2.8% | 2.5% |
| fademem_lml_dormant | 2.3% | 97.8% | 18.5% | 1.9% | 0.0% |
| pragma_dormant | 3.3% | 96.8% | 20.7% | 1.9% | 0.0% |
| pragma_revive | 3.3% | 96.8% | 65.1% | 89.6% | **96.8%** |

top-5 和 top-20 的趨勢相同（`runs/diagnostics/stale_decay/summary.json`）。不衰退時，提問時取得 m_n 的比例在 top-5／10／20 分別是 46.5%／65.1%／76.3%。

### 1.3 解讀

1. **不衰退時，寫入時裁決是可行的**：新證據到來時，BM25 有 93.5% 的機率找到舊證據。
2. **照 FadeMem 論文的參數衰退，新舊證據一起消失**：提問時取得新證據的比例從 65.1% 掉到 6.3%。原因是 STALE 的證據都不在最後，新證據到提問時也已經過了約 100 天，而最近的干擾對話強度最高。在沒有中途存取的情況下，衰退等於「只記得最近的事」。
3. **（已被 §1.6 修正，96.8% 是上界）Pragma 式的分工會產生「被遮蔽的修訂」**：Pragma 在寫入新情節時，先把沉寂的情節移出，再只對活躍情節做重新詮釋（`core/tools/episode_consolidate/tool.py`，sweep 在 reconsolidation 之前，候選只來自活躍目錄）；提問時的回憶則會搜尋沉寂情節並把選中的喚醒（`core/curator.py`）。在 STALE 上，96.8% 的案例中舊記憶在新證據到來時已經沉寂、無法被重新詮釋，但到提問時又被喚醒並取回。

### 1.4 這個診斷**不能**說明的事

- **答題對錯**：這裡只量檢索。舊記憶被取回不等於答錯，新證據沒取回也不一定答錯。答題層級要在本機用正式模型跑（§1.5）。
- **FadeMem 的完整行為**：重要度、存取強化、衝突消解都沒實作；STALE 中途沒有提問，存取強化本來也不會發生。
- **Pragma 的完整行為**：Pragma 以「情節」為單位、每次只重讀最相近的 3 個，這裡以一問一答為單位、取前 10 個，只是近似。初始強度 0.5 是假設值（Pragma 由模型決定）。
- **稠密檢索**：只測了 BM25。

### 1.5 答題層級的後續（在 Z13 上執行）

`configs/local/stale__rag_bm25_decay_*.toml` 三個範本只和 `stale__rag_bm25.toml` 差在 `decay` 一行。跑完 `wlmem run` 和 `wlmem evaluate` 後：

```powershell
python scripts\decompose_stale_errors.py runs\<run_name>
```

它把每個探測問題分到「新證據是否在 context」×「舊證據是否在 context」×「judge 是否通過」的格子，區分：

- 新證據不在 context 而答錯：檢索失敗；
- 新證據在 context 仍答錯：使用失敗（STALE 論文所說的「取回了但沒有採用」）。

judge 必須先通過實驗協定 §6 的人工一致性驗證。

### 1.6 修正：Pragma 每一輪對話都會喚醒記憶（2026-11-11，讀完正式論文後）

**錯在哪裡**：§1.2 的 `pragma_revive` 假設喚醒只發生在最後提問時。Pragma 論文（Santi 2026, *Knowledge-Based Systems* 353:117193，Table 3、Algorithm 1）和原始碼（`core/curator.py`：「a live session curates once per turn」）都顯示，Curator 在**每一輪使用者發言前**都會從活躍和沉寂情節中挑候選、由模型選擇，選中的沉寂情節立刻喚醒並重設衰退時鐘。所以在新證據到來的那個 session 裡，舊記憶 m_o 有機會先被喚醒，session 結束後的重新詮釋就看得到它。96.8% 是 Curator 從不選 m_o 時的數字，也就是上界。

**重現**：`python scripts/diagnose_pragma_curator.py --pragma <Pragma checkout>`（Pragma @`e53eace` 的關鍵字路徑；一個 STALE session 當一個情節；情節文字以 session 原文近似 Pragma 由模型寫的敘事；不呼叫模型）。

| 量測 | 結果 |
|---|---|
| 新證據 session 中，m_o 至少在一輪被列入 Curator 的 10 個候選 | 82.8% |
| 第一輪就被列入 | 55.5% |
| m_o 若已喚醒，會落在重新詮釋的前 3 個相近情節內 | 53.0% |
| 兩者皆是（**重新詮釋能觸及 m_o 的上界**） | 52.3% |

**修正後的解讀**：

- 在 Pragma 的實際流程下，「新證據到來時舊記憶修訂不到」的比例介於 **47.7%（Curator 每次都選 m_o）到 96.8%（從不選）**之間。實際落點取決於 Curator 模型會不會為了回答當下對話而選一段舊記憶，這要用本機模型實測。
- **即使完全不衰退，重新詮釋也只觸及 53% 的 m_o**，因為 Pragma 每次只重讀最相近的 3 個情節。修訂觸及不到舊記憶，有一部分原因是候選數上限，不只是衰退。
- Pragma 已經**隱含地**把喚醒和修訂接在一起：同一個 session 中先由 Curator 喚醒，結束後再重新詮釋。只是喚醒的標準是「對回答當下對話有沒有用」，不是「這段記憶會不會被新證據推翻」。§1.3 第 3 點原本說「喚醒時不會修訂」，嚴格來說只在最後提問那一刻成立。

**可在 Z13 上補做的低成本實測**：每個 STALE 案例只對新證據 session 的各輪呼叫一次 Pragma 的 Curator 提示（約 400 個案例 × 中位數 4 輪），量「m_o 被列為候選時，模型選它的比例」。這可以把上述區間收斂成一個數字，不需要跑完整的 Pragma。
